클러스터 지식 시작하기

따로 입력할 정보는 없고 클러스터 이름만 정하면 됩니다. KOA 는 이 이름으로 지식·트리아지·조사 요청을 묶습니다. 이름은 탐색 결과(koa/discover.py)나 읽기 전용 kubeconfig 컨텍스트에서 -readonly 를 뺀 것과 같아야 트리아지 결과와 맞습니다.

직접 입력

시작하면 탐색에서 찾은 메시지 큐·캐시·ingress 가 구성요소로 미리 들어갑니다. 나머지(앱 워크로드, 흐름)는 "클러스터 지식" 탭에서 표로 채웁니다. 워크로드 칸은 클러스터의 실제 목록에서 고를 수 있습니다.

무엇이 문제인가요?

평소 말로 쓰면 됩니다. 예: "rmq 소비가 안 되는데 어디가 문제야?", "주문 API 가 30분 전부터 느려". 클러스터 지식으로 대상·증상·확인 순서를 바로 정리해 보여 줍니다.

구성요소

사람이 부르는 이름 → k8s 워크로드(네임스페이스/종류/이름). 별칭은 질문 속 단어를 찾는 데 씁니다 (쉼표로 구분). 클러스터 밖(DB 등)은 "밖"에 체크하고, 호출하는 쪽 로그에 남는 오류 문구를 적어 주세요.

흐름

요청이 지나가는 길을 순서대로. 역할: call 동기 호출, produce 큐에 넣기, consume 큐에서 꺼내기. 분석은 이 길을 따라 "정상 → 비정상으로 바뀌는 첫 지점"을 찾습니다.

정상 패턴

정상인데 이상해 보이는 것 (오탐 줄이기). 예: 매일 02:00 배치 때 큐가 쌓였다 빠진다.
