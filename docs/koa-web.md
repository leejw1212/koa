# KOA 웹 화면

> 2026-10-06 · 첫 버전 · 설계 바탕: [koa-analysis-inputs.md](koa-analysis-inputs.md)

## 왜

클러스터 지식(`flows.yaml`, `incidents/*.md`)을 YAML 로 직접 쓰기 어렵고, 조사 요청과 결과가 채팅 기록에만 남는다.
웹 화면은 같은 파일을 표와 폼으로 고치고, 조사 요청을 남기고, 결과를 한곳에서 보게 한다. 파일 형식은 그대로라
채팅으로 넣든, 웹으로 넣든, 파일을 직접 고치든 결과가 같다.

## 실행

```bash
cd ~/.hermes/profiles/koa          # 개발 체크아웃이면 저장소 루트
python3 koa/web.py                 # http://127.0.0.1:8765  (--port 로 변경)
```

추가 설치 없음 (Python 3.9+ 표준 라이브러리 + 이미 쓰는 PyYAML). 브라우저 화면도 외부 CDN 을 쓰지 않는다.

## 화면

| 탭 | 하는 일 | 파일 |
|---|---|---|
| 조사 요청 | 평소 말로 질문 → 조사 계획(대상·증상·확인 순서·과거 이슈)을 입력하는 대로 미리 보여 줌 → 저장하면 트리아지 실행 | `local/requests/<클러스터>/<시각>/request.yaml`, `triage.txt` |
| 결과 | 요청 목록, 조사 계획, 트리아지 출력, KOA 채팅에 붙여 넣을 한 줄, KOA 가 쓴 분석 결과 | 같은 폴더 `report.md` |
| 클러스터 지식 | 자유 글 편집기 (왼쪽) + "KOA 가 이해한 것" (오른쪽: 흐름 그림, 구성요소·워크로드·별명, 정상 패턴, 확인할 것). 쓰는 동안 바로 바뀜 | `architecture.md` (글), `flows.yaml` (글에서 자동 생성) |
| 과거 이슈 | 있었던 일을 글로. 날짜·증상·구성요소·따옴표 로그 문구·"원인:" 을 뽑아 머리말로 저장 | `local/knowledge/<클러스터>/incidents/*.md` |

처음 열면 "클러스터 지식 시작하기" 가 나온다. 입력할 것은 **클러스터 이름 하나**다. 화면이 탐색 결과
(`<결과>/<이름>.yaml`)와 읽기 전용 kubeconfig 컨텍스트(`-readonly` 를 뺀 이름)에서 후보를 찾아 버튼으로 보여 주므로
보통은 누르기만 하면 된다. 이름이 같아야 트리아지 결과와 묶인다.

- 시작하면 탐색에서 찾은 메시지 큐·캐시·ingress 가 구성요소로 미리 들어간다 (관측·GitOps 네임스페이스의 것은 뺀다).
- 구성요소의 워크로드 칸은 읽기 전용 kubeconfig 로 가져온 Deployment·StatefulSet·DaemonSet 목록에서 고를 수 있고, 고르면 이름이 채워진다 (못 가져오면 직접 입력).
- "예시로 채워서 연습" 을 켜면 템플릿 예시(order-api 등)로 시작한다. 실제 클러스터에 쓰면 예시가 분석 경로에 섞이므로 연습용으로만.
- 지식 없이도 조사 요청은 된다 (트리아지만으로 본다).

## 자유 글 → 구조 (`koa/freeform.py`)

표나 YAML 로 넣지 않는다. 사람은 `architecture.md` 에 말하듯 쓰고, 저장할 때 아래 줄만 뽑아 `flows.yaml` 을 다시 만든다
(직접 고친 `flows.yaml` 은 덮이고, 직전 파일은 `flows.yaml.bak`). 규칙에 안 맞는 글은 분석 때 참고로 읽는다.

| 쓰는 법 | 뽑는 것 |
|---|---|
| `사용자 → ingress-nginx → gateway → order-api → orders-db` | 흐름 (→ -> => ⇒). '사용자' 같은 말은 건너뜀 |
| `order-api → rabbitmq(rmq, 래빗) → order-worker` | 큐(rabbit·kafka·sqs·큐 …)를 지나면 넣기/꺼내기, 괄호 안은 별명 |
| `orders-db: 주문 DB, mysql, 클러스터 밖` | 콜론 뒤 짧은 쉼표 목록은 별명, '밖·외부·RDS' 는 클러스터 밖 |
| `order-worker 는 shop/Deployment/order-worker 이고 컨슈머라고도 불러` | 워크로드, "…라고 불러" 앞은 별명 |
| `orders-db 가 죽으면 "Too many connections" 가 찍힌다` | 따옴표 = 그 구성요소의 로그 문구 |
| `매일 02:00 배치 때 order-worker 큐가 쌓였다 빠진다` | 정상 패턴 |

워크로드를 안 적으면 읽기 전용 kubeconfig 로 가져온 워크로드 목록에서 같은 이름을 찾아 붙인다. 이름이 db·rds·mysql 같은데
워크로드가 없으면 클러스터 밖으로 본다. `<!-- -->` 안은 읽지 않는다 (새 클러스터의 안내문).

## 디자인

글래스 스타일 (반투명 패널 + 배경 블러, 그라디언트 강조), 밝은·어두운 모드 둘 다, 휴대폰 폭에서 한 줄로. 외부 폰트·CDN 없음.

## 분석과의 연결

웹 화면은 LLM 을 부르지 않는다. 조사 계획(`koa/knowledge.py plan`)과 트리아지(`koa/triage.py`)까지 만들고,
분석은 기존처럼 KOA 채팅에서 한다.

1. 웹에서 요청 저장 → `request.yaml`(계획) + `triage.txt`(트리아지, `--ns` 는 계획 경로의 네임스페이스)
2. 결과 화면의 한 줄을 KOA 채팅에 붙여 넣음: "local/requests/…/request.yaml 의 조사 요청을 분석해줘. 결과는 같은 폴더의 report.md 에 써줘."
3. `cluster-incident-analysis` 스킬 0단계가 계획·트리아지를 읽고 경로를 따라 확인한 뒤 `report.md` 를 씀
4. 결과 화면이 3초마다 다시 읽어 `report.md` 를 보여 줌

설계 문서는 조사 기록을 `local/clusters/<클러스터>.triage/` 에 두는 안이었는데, 요청·계획·트리아지·결과를
한 폴더로 묶으려고 `local/requests/` 로 정했다.

## 안전

- 127.0.0.1 에만 열고, 다른 주소로 여는 옵션은 두지 않는다 (인증이 없고, 지식에 회사 내부 이름이 들어간다).
- Host 헤더가 localhost 가 아니면 거부 (DNS 리바인딩), 쓰기 요청은 `X-KOA: 1` 헤더가 있어야 한다 (다른 사이트의 폼 전송 차단).
- 하는 일은 `local/` 아래 파일 읽기·쓰기와 읽기 전용 트리아지 실행뿐. 클러스터는 바꾸지 않는다.
- `flows.yaml` 을 저장하면 직전 파일을 `flows.yaml.bak` 으로 남긴다. 화면에서 저장하면 YAML 주석은 없어진다.

## 조사 계획 규칙 (`koa/knowledge.py`)

| 항목 | 규칙 |
|---|---|
| 대상 | 질문 안에 구성요소 이름·별칭이 들어 있으면 그것 (가장 긴 일치). 없으면 트리아지 상위 이상 징후로 |
| 증상 유형 | 질문 문구 (소비·쌓임 → queue-backlog, 느려·타임아웃 → latency, 5xx·에러 → errors, 재시작·죽 → crash …) |
| 기간 | "30분", "2시간" 같은 말, 없으면 1h. 화면에서 직접 지정 가능 |
| 확인 순서 | queue-backlog: 소비자 → 브로커 → 소비자의 하류 → 생산자 / crash·pending: 대상 → 대상의 하류 / 그 외: 흐름 순서 |
| 과거 이슈 | 유형이나 대상이 같거나, 경로 위 구성요소가 둘 이상 겹치는 것 |

## 확인한 것 (2026-10-06, 개발 컨테이너)

- 템플릿 지식으로 질문 4개 → 계획: "rmq 소비가 안 되는데" → rabbitmq/queue-backlog, 소비자부터 4단계 + 디스크 알람 이슈,
  "주문 API 가 30분 전부터 느려" → order-api/latency/30m, "주문 워커 계속 재시작해" → order-worker/crash, "로그가 안 보여" → 대상 없음/log-pipeline.
- 브라우저(Chromium)로 구성요소 추가 → 저장 → 검사 경고 줄어듦, 과거 이슈 추가 → 다음 질문의 계획에 1순위로 나옴, 요청 저장 → 결과 화면.
- 트리아지는 이 컨테이너에 클러스터가 없어 "kubeconfig 없음" 으로 실패하는 것까지만 확인 (실패 출력이 결과 화면에 그대로 보임). kind-lab 에서 확인 필요.
